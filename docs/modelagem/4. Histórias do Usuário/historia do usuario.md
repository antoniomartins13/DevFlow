# História do usuario

| ID | História do usuário |
| --- | --- |
| **HU-01 — Registrar demanda** | Como **solicitante**, quero registrar uma demanda com objetivo, contexto e critérios de aceite, para que a equipe e os agentes entendam o resultado esperado. |
| **HU-02 — Preparar solução** | Como **responsável**, quero receber uma especificação, um plano e, quando necessário, diagramas ou protótipo, para avaliar a solução antes da implementação. |
| **HU-03 — Autorizar etapas** | Como **responsável**, quero aprovar ou rejeitar os checkpoints com informações objetivas, para controlar o avanço da tarefa sem acompanhar cada ação do agente. |
| **HU-04 — Executar tarefa** | Como **desenvolvedor**, quero que o DevFlow execute uma tarefa autorizada em um worktree isolado, para preservar o trabalho existente no repositório. |
| **HU-05 — Verificar alteração** | Como **desenvolvedor**, quero que as verificações obrigatórias do projeto sejam executadas e seus resultados registrados, para identificar falhas antes da abertura do MR. |
| **HU-06 — Receber revisão independente** | Como **revisor humano**, quero receber uma análise independente do diff, incluindo riscos e testes removidos ou enfraquecidos, para orientar minha revisão. |
| **HU-07 — Corrigir achados** | Como **desenvolvedor**, quero que achados verificáveis sejam encaminhados para correção e nova verificação, para resolver problemas antes da validação. |
| **HU-08 — Receber MR em draft** | Como **revisor humano**, quero receber um MR em draft com descrição, evidências e pendências, para avaliar a entrega e decidir sobre o merge. |
| **HU-09 — Validar com roteiro** | Como **validador**, quero receber passos e resultados esperados para funcionalidade, casos de borda e regressões indiretas, para saber exatamente o que testar. |
| **HU-10 — Acompanhar tarefas** | Como **integrante da equipe**, quero consultar o estado, os resultados e os bloqueios de cada tarefa, para entender o andamento e o próximo passo. |
| **HU-11 — Receber pedidos de decisão** | Como **responsável**, quero receber notificações e perguntas objetivas no Mattermost, com links e evidências, para decidir com menos esforço. |
| **HU-12 — Retomar trabalho** | Como **operador**, quero retomar tarefas após interrupções preservando estado, aprovações e evidências, para evitar perda de contexto e ações duplicadas. |
| **HU-13 — Tratar dependências** | Como **responsável**, quero que tarefas independentes possam avançar enquanto outras aguardam dependências, para evitar bloqueios desnecessários. |
| **HU-14 — Controlar consumo** | Como **responsável**, quero configurar limites e acompanhar o consumo das execuções, para usar as assinaturas dentro do orçamento disponível. |
| **HU-15 — Configurar projetos e agentes** | Como **operador**, quero configurar repositórios, verificações e executores por etapa, para atender diferentes projetos e tecnologias. |
| **HU-16 — Manter o DevFlow confiável** | Como **mantenedor**, quero testar o próprio DevFlow com agentes e APIs simulados e exigir CI verde, para alterar o pipeline sem gastar cota nem comprometer seu funcionamento. |
| **HU-17 — Avaliar melhorias** | Como **responsável**, quero receber propostas baseadas em problemas observados e comparações mensuráveis, para adotar somente mudanças que justifiquem seu custo e complexidade. |
| **HU-18 — Aproveitar novos modelos** | Como **responsável**, quero comparar novos modelos e configurações por etapa, para aproveitar avanços comprovados sem perder os controles existentes. |
